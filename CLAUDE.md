# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single, self-contained HTML file (`index.html`) that generates printable A4/A5 math-practice worksheets (multiplication, division, addition, subtraction) for young children, drawn on a squared-notebook grid. The UI and worksheet labels are localized (Hungarian by default, English selectable), and each sheet can carry an optional footer with the site link and a QR code. Open the file in a browser to use it — it works fully offline (the one dependency, jsPDF, is inlined into the file at build time). It is also published via GitHub Pages at https://ksisu.github.io/math-worksheet-generator/ (served from `index.html` on `main`).

- **Run/test:** open `index.html` in a browser. The control panel is on the left; **Generate** rebuilds the preview, **Download PDF** saves a real vector PDF.
- **Build:** `npm install && npm run build`. `build.js` inlines `node_modules/jspdf/dist/jspdf.umd.min.js` between the `<!-- jspdf:start -->` / `<!-- jspdf:end -->` markers in the HTML (idempotent). Re-run **only** after `npm install` or a jsPDF version bump — editing the app's own JS in the HTML needs no rebuild. The inlined jsPDF blob is committed (that's what keeps the file offline-standalone); `node_modules/` is gitignored.
- **The output's exact printed look is the product.** The grid size/color, per-cell digit placement, and the answer-space box were tuned over many print iterations. Treat the visual parameters as finalized defaults; the functional code can be reshaped around them. `SPEC_math_worksheet_generator.md` is the authoritative spec — read it before changing layout/print behavior.

## Architecture (all inside the one HTML file)

The `<script>` is a small pipeline:

1. `readConfig()` — reads control-panel inputs into a `cfg` object. Includes the chosen page (`pageSize` `a4`/`a5` → `pageW`/`pageH`/`jsformat` from the `PAGE_SIZES` table), the toggles (`showOperandBox`/`showResultBox`/`showGrid`/`alignOps`/`alignEq`/`showFooter`, `mulSymbol`/`divSymbol`), and the geometry from `pageGeometry()`. `marginTop` is in mm; `marginLeft` is computed as `(cfg.pageW − gridCols·cellmm)/2` to **center** the fixed-width grid horizontally on the page (~10 mm each side on A4).
2. `makeProblem(cfg)` — picks one enabled task type and produces one problem `{a, b, op, type, missing, res, fw, rw}`. `op` is `mul`/`div`/`add`/`sub`; `type` (the variant) is `result`/`missing`; `fw`/`rw` are the fixed cell-widths of the missing-operand box and the result field. ×: operands from the chosen tables × 1–10. ÷: shares the times tables (dividend is a product, so the quotient is whole). +/−: operands obey the chosen range so the *answer* stays in it (sum ≤ N; subtraction `0–N` keeps a≥b, `±N` allows a negative answer).
3. `tokensFor(problem, cfg)` — converts a problem into an ordered list of cell tokens: `{t:'char', v}` per digit, `{t:'op', v}` for a `+`/`−` operator (the × and ÷ glyphs come from `cfg.mulSymbol`/`cfg.divSymbol`), or `{t:'miss', w, kind}` for a fill-in field (the missing-operand box `w=fw, kind:'operand'`, or the empty result field `w=rw, kind:'result'`). The field always reserves its cells; whether a box is drawn is decided at layout time by `cfg.showOperandBox`/`cfg.showResultBox` per `kind`.
4. `layoutSheet(problems, cfg)` — **the single source of truth for placement.** Runs the block/row math over `tokensFor` and returns `{totalCols, totalRows, placements}` with each placement in cell units: `{type:'char'|'dot'|'op'|'box', col, row, ch?, w?}`. Both renderers consume this so the on-screen preview and the PDF agree exactly.
5. `buildSheet(...)` — DOM renderer over `layoutSheet` output (CSS gradient grid + absolutely-positioned mm cells) for the preview / browser print. When `cfg.showFooter` is on it also appends the footer (`.sheet .footer`) in the bottom page margin: the `SITE_URL` text plus a QR canvas from `makeQRCanvas()` (drawn from the inlined `QR_MATRIX`).
6. `renderSheetToPDF(doc, layout, cfg, label, isFirstPage)` — jsPDF **vector** renderer over the same `layoutSheet` output, in `unit:'mm'`: grid as `doc.line` strokes (drawn only when `cfg.showGrid` is on), digits/operators as centered `doc.text`, the `·` multiplication dot / `:` division colon (two stacked dots) as filled `doc.circle`s, `+`/`−` as thin `doc.line` bars, each fill-in box as one `doc.rect` spanning its `w` cells. When `cfg.showFooter` is on, the same footer is drawn below the grid: `SITE_URL` as `doc.text` and the `QR_MATRIX` as one `doc.rect` per dark module.
7. `generate()` — loops `cfg.pages`, slicing the problems across pages, appends preview sheets, and records each rendered page (`{problems, cfg, label}`) into the module-level `lastRender`. `downloadPDF()` replays `lastRender` through `layoutSheet` → `renderSheetToPDF` so the PDF is exactly what's on screen. `generate()` also rewrites the `@page` size rule (`<style id="pageRule">`) to match `cfg.pageSize`.

**Localization (i18n).** Strings live in the `I18N` table keyed by language (`en`/`hu`), looked up via `tr(key)` (falls back to English, then the raw key). The current `lang` is read from `localStorage['mwg-lang']`, defaulting to `'hu'`. `applyLanguage()` re-renders every `[data-i18n]` node, refreshes the symbol/hint/label texts, and regenerates the preview; it runs on load and whenever the `#lang` selector changes. Both UI controls and the worksheet's operation/variant labels are translated.

## Layout model — must stay consistent across spec, CSS, and JS

- **Grid is a CSS `repeating-linear-gradient`** (in `:root`/`.grid`), not DOM cells — deterministic when printing. Characters/boxes are `position:absolute`, placed in **mm** (`left=col*cellmm`, `top=row*cellmm`). CSS grid was tried and abandoned (rows collapsed on print).
- **Block geometry & page layout** (`pageGeometry()` in the script, stored on `cfg`, consumed by `layoutSheet`): `BLOCK = max over enabled types of (2·opW + 2 + resW) + GAP(1)` cells wide per problem (`opW`=operand digits, `resW`=result-field width, +1 each for the operator and `=`); `rowPitch=2`. ×-only stays `BLOCK=10` (`opW=2,resW=3`); +/− widen it. `widthsFor()` computes `opW`/`resW` per type — keep it in sync with the spec. **Columns and pagination are computed, not user-set, and derive from the chosen page size**: the cell is fixed at 5 mm, a row fits `USABLE_COLS = floor((pageW − 2·10)/5)` squares (A4 **38**, A5 **25**) so `cols = floor((USABLE_COLS+GAP)/BLOCK)`, and `ROWS_PER_PAGE = floor((floor((pageH − 2·14)/5)+1)/2)` (A4 **27**, A5 **18**) → `perPage = cols·ROWS_PER_PAGE`. `pageGeometry(types, align, page)` computes all of this from the `page` (`PAGE_SIZES[a4|a5]`). The Layout selector toggles between a problem count (→ `ceil(total/perPage)` pages, last partial) and a sheet count (→ full pages); `generate()` paginates accordingly. The **grid itself is always drawn at the full working area** (`gridCols=USABLE_COLS × gridRows=ROWS_PER_PAGE·2−1`, from `pageGeometry` — A4 38×53, A5 25×35), so every page — even a partial last one — looks like a complete sheet of squared paper. Within a row the column-blocks are **distributed like `justify-content: space-between`** (computed `colX` in `layoutSheet`: first flush-left, last flush-right, leftover columns spread as whole-cell gaps); rows stay top-packed. Two Display-option toggles right-align operands into fixed columns: `alignOps` (operator column, **off by default**) and `alignEq` (`=` column, **on by default** — so the default output already aligns the `=`); either one widens `BLOCK` to `2·OPW+2+RESW+GAP` and is emitted as `{t:'gap',w}` padding tokens so both renderers stay in sync.
- **Fill-in box** (missing-operand or empty result) is a *single* element spanning `w` cells (never per-cell frames — avoids a doubled center line) and extends ~one grid-line past its right/bottom boundary to compensate for the inward-drawn gradient lines. Drawn per `kind`: the operand box when `cfg.showOperandBox` is on (**default on**), the result box when `cfg.showResultBox` is on (**default off**). A separate **`showGrid`** toggle (**default on**) hides the whole grid when off — DOM via a `nogrid` class, PDF by skipping the grid lines. The **`showFooter`** toggle (**default on**) draws the site-link + QR footer in the bottom page margin (below the grid, off the squared area) in both renderers.
- **Operators are special placements, not plain chars.** `·` (× default) is a `dot` placement and `:` (÷ default) is two stacked `dot`s (CSS `.ch.dot` / PDF `doc.circle`). `+` and `−` are `op` placements drawn as thin (non-bold, ~0.07·cell) **vector bars** (DOM: `.ch.op` `::before`/`::after`; PDF: `doc.line`), ~80% of the cell so they almost touch the cell lines — sized to match in preview and PDF. `tokensFor` emits `{t:'op'}` only for the operator, so a `−` that's a **negative-result sign** stays a normal `char`. The ×/÷ glyphs are selectable in Display options (`mulSymbol` ·/×/\*, `divSymbol` :/÷//); when chosen, `×`, `*`, `÷`, `/` render as ordinary centered text (the `*` gets a vertical nudge) rather than the drawn dot/colon.

## Gotchas

- **ID collisions** silently break generation: `querySelector` grabs the wrong element and the sheet renders empty. Keep input IDs distinct from container IDs (notably do not reuse `sheets`).
- **Visual parameters live in `:root` CSS variables** (cell size, grid color/line, box color/line, margins). The cell is **fixed at 5 mm** (`--cell-mm`, also `cfg.cellmm=5`, set per-sheet via `style.setProperty`); columns/pagination derive from it (see Block geometry above).
- When printing, background graphics must be enabled so the grid gradient prints; suggest the browser's "Fit to page" if an edge runs off. The grid is **centered** horizontally (`marginLeft = (cfg.pageW − gridCols·cellmm)/2` in `readConfig`, ~10 mm each side on A4); the grid is always narrower than the chosen page (A4: 190 mm within 210 mm; A5: 125 mm within 148 mm). `generate()` keeps the `@page` size rule in sync with `cfg.pageSize`.
